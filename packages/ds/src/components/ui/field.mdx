# Field

A form field wrapper that combines a label, a single form control, and an optional description or error message.

Field is a composition wrapper. It is not a form control. It has no border, background, radius, or other chrome. Width follows the parent. Height follows its content.

In Figma, Field has one variant: `optional` (`false` | `true`). Supporting copy is not a Field variant. It is the `description` slot (on or off), filled with a string or with `FieldDescriptionOrRequirement`.

## When to use

Use Field when a control needs a visible label and, optionally, supporting text or an error message.

Pair it with existing controls:

- `Input`
- `Select`
- `Textarea`
- `CheckboxGroup`
- `RadioGroup`

Do not use Field to restyle those controls. Each control keeps its own states, including `error`, `disabled`, and interaction.

## Composition

The Figma control slot maps to React `children`. Pass one control. Field does not clone children or inject props.

```tsx
<Field label="Email" htmlFor="email">
  <Input id="email" placeholder="you@example.com" />
</Field>
```

## Label

Pass `label` to render the label row. Omit `label` to hide it. There is no `showLabel` prop.

The existing `Label` component renders the name. Pass `htmlFor` on Field and the same `id` on the control so clicking the label focuses the control.

```tsx
<Field label="Email" htmlFor="email">
  <Input id="email" />
</Field>
```

## Optional fields

Set `optional` to show a muted `(optional)` marker next to the label. This is the only Figma variant. The React default is `false`. There is no required asterisk and no `required` visual prop. HTML `required` belongs on the control.

```tsx
<Field label="Nickname" optional htmlFor="nickname">
  <Input id="nickname" />
</Field>
```

## Description vs error

Field has one supporting slot below the control. Figma no longer has a `support message` variant (`none` / `description` / `error`). Omit `description` to hide the slot; pass it to show it.

- No `description` — no support text
- `description` as a string — helper copy, no icon
- `description` as a string + `error` — destructive copy, no icon
- `description` as `FieldDescriptionOrRequirement` (one or more) — each row owns its `state` and icon

`error` is a string shortcut: it sets the wrapped line to `state="invalid"`. It is not the removed Figma `support message` variant. Do not pass a helper string and a requirement list at the same time. There are no separate `helperText` or `errorMessage` props.

```tsx
<Field
  label="Email"
  htmlFor="email"
  description="We’ll never share your email with anyone else."
>
  <Input id="email" aria-describedby="email-description" />
</Field>
```

<Canvas of={FieldStories.Description} />

Field’s `error` prop only styles a string `description`. It does **not** set `error` on the child. Set both when the control should look invalid:

```tsx
<Field
  label="Email"
  htmlFor="email"
  description="Please enter a valid email address."
  error
>
  <Input id="email" error aria-describedby="email-description" />
</Field>
```

<Canvas of={FieldStories.Error} />

When both `htmlFor` and `description` are set, the slot wrapper’s `id` is `` `${htmlFor}-description` ``. Pass that same value as `aria-describedby` on the control. Field does not inject `aria-describedby` into children.

`error` on Field does not recolor `FieldDescriptionOrRequirement` rows. Those rows keep their own `state`.

## Accessibility

- Field renders a `<div>`. It does not add a Field-level ARIA role.
- The label is the existing `Label` component. Pair `htmlFor` with the control’s `id`.
- `(optional)` is rendered inside the label so it is part of the accessible name.
- `disabled`, `required`, `aria-invalid`, and the control’s visual error state belong on the child.
- Field does not clone children or set `error` / `id` / `aria-describedby` on them.
- Wire `aria-describedby` on the control when a description is present, using `` `${htmlFor}-description` `` on the slot wrapper.
- For CheckboxGroup and RadioGroup, prefer the Field label as a visual heading and keep item-level names on each control.

## API

| Prop | Type | Default | Description |
| --- | --- | --- | --- |
| `children` | `React.ReactNode` | — | The form control. |
| `label` | `React.ReactNode` | — | Visible field name. Omit to hide the label row. |
| `optional` | `boolean` | `false` | Figma variant. Shows an “(optional)” marker next to the label. |
| `description` | `React.ReactNode` | — | Supporting slot. Omit to hide. A string is helper or error copy. A node is rendered as-is. |
| `error` | `boolean` | `false` | String shortcut to `invalid`. Not a Figma variant. Does not set `error` on the child or recolor requirement rows. |
| `htmlFor` | `string` | — | Associates the label with a control. Match this to the control’s `id`. |
| `className` | `string` | — | Adds custom CSS classes to the Field root. |

The component also supports the standard HTML `<div>` attributes through `React.ComponentProps<"div">`. Native `id` belongs to the Field root, not the nested control.

There are no `supportMessage`, `showLabel`, `control`, `required`, `disabled`, `value`, `placeholder`, `size`, `state`, `variant`, `helperText`, or `errorMessage` props.
