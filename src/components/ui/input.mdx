# Input

A single-line form control for collecting user input. Supports `text`, `email`, and `password` types, decorative leading/trailing icons, a generic trailing slot, and validation styling.

## Email

`type="email"` renders a native `<input type="email">`. Keyboard, autofill, and browser validation behavior all come from the browser. Pair it with `autoComplete="email"` when the field collects an email address.

## Password

`type="password"` renders a native `<input type="password">`. Masking, autofill, and browser password-manager behavior all come from the browser. Input does not own a reveal/hide toggle — compose one through `trailing` if needed.

## Trailing slot

`trailing` renders arbitrary React content after the value. Use it for interactive controls. `trailingIcon` remains a decorative `IconName` and does not accept interaction.

If both are passed, `trailing` is rendered and `trailingIcon` is ignored.

Password visibility is a composition example. Input does not add password-specific props. The consumer owns the visible state and toggles `type` between `"password"` and `"text"`.

```tsx
<Input
  type={visible ? "text" : "password"}
  trailing={
    <Button
      type="button"
      variant="ghost"
      size="icon-xs"
      icon={visible ? "eye-off" : "eye"}
      aria-label={visible ? "Hide password" : "Show password"}
      onClick={() => setVisible((value) => !value)}
    />
  }
/>
```

Interactive controls inside `trailing` must have an accessible name. When the Input is inside a form, use `type="button"` so the control does not submit.

## Filled

There is no `filled` prop. Whether the input shows placeholder styling or value styling is determined entirely by the native input's value — pass `value`/`defaultValue` like any other input.

Set `error` to mark the field as invalid. This mirrors `aria-invalid="true"` on the underlying `<input>`, which drives both the destructive styling and the accessibility signal from a single source of truth.

Use the native `disabled` prop. If `disabled` and `error` are both set, the disabled appearance takes precedence.

## Associating with a Label

`Input` does not render its own label. Pair it with the existing `Label` component using `htmlFor` / `id`, the same pattern used for any native form control.

```tsx
<Label htmlFor="email">Email</Label>
<Input id="email" type="email" autoComplete="email" placeholder="you@example.com" />
```

## Accessibility

- Renders a native `<input>`, so keyboard behavior, focus, and typing all come from the browser.
- `error` is mirrored to `aria-invalid` — style and semantics stay in sync automatically.
- Pointer focus on the native input produces the 2px strong focus border. Keyboard focus on the native input uses that same strong border plus the `intent-keyboard` focus ring. Both are derived from `:has([data-slot=input]:focus)` on the wrapper, so a focused trailing control does not restyle the field.
- Leading/trailing icons are decorative and marked `aria-hidden`; they never carry the field's accessible name.
- `trailing` is independently focusable. Give that control an accessible name. Use `type="button"` when it is a button inside a form.
- `Input` intentionally does not include a label. Always pair it with a `Label` (or `aria-label`/`aria-labelledby`) so the field has an accessible name.

## API

| Prop | Type | Default | Description |
| --- | --- | --- | --- |
| `type` | `"text"` &#124; `"password"` &#124; `"email"` | `"text"` | Native input type. All types share the same chrome; native type behavior comes from the browser. |
| `error` | `boolean` | `false` | Marks the input as invalid. Mirrored to `aria-invalid`. |
| `leadingIcon` | `IconName` | — | Decorative icon displayed before the value/placeholder. |
| `trailingIcon` | `IconName` | — | Decorative icon displayed after the value/placeholder. Ignored when `trailing` is set. |
| `trailing` | `React.ReactNode` | — | Interactive or custom content rendered after the value. The consumer owns the control. |
| `disabled` | `boolean` | `false` | Prevents interaction with the input. |
| `placeholder` | `string` | — | Placeholder text shown when the input is empty. |
| `className` | `string` | — | Adds custom CSS classes to the input's wrapper. |

The component also supports the standard HTML `<input>` attributes (`value`, `defaultValue`, `name`, `id`, `onChange`, etc.) through `React.ComponentProps<"input">`, excluding `type` and `size`, which are replaced by the constrained `type` prop above.

There are no `focus`, `filled`, or `focusFilled` props — those are interaction states derived automatically from the native input and CSS, not from React.
